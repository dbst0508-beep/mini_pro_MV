## 2. 클래스·함수 단위 코드리뷰

이번 작업은 **코드 변경이 없어** 리뷰할 클래스·함수가 없다. 대신 README에서 쓴 HTML 태그를 정리한다.

| 항목 | 역할 |
|---|---|
| `<img src="..." width="320">` | 이미지를 가로 320px로 표시. 마크다운 `![](..)`는 크기를 못 정해서 HTML 태그를 씀 |
| 연속된 `<img>` | 줄바꿈 없이 이어 쓰면 화면이 넓을 때 옆으로 나란히 배치됨 |
| 경로 `docs/images/web/…` | README는 저장소 루트에 있어서 `docs/`부터 시작하는 상대 경로를 씀 |

## 4. 복습

### 화면 기록은 "흐름 순서"로
- 파일 이름 순이 아니라 사용자가 겪는 순서(가입 → 피드 → 분석 → 마이페이지)로 놓으면 처음 보는 사람이 따라가기 쉽다.
- 정상 화면뿐 아니라 **오류·실패 화면**(비밀번호 규칙 위반, LLM 실패)도 넣으면 "예외를 처리한다"는 증거가 된다.

### 이미지 파일명 규칙
- 영문 소문자 + 하이픈(kebab-case)으로 통일한다. 공백·한글이 있으면 마크다운 링크가 깨지거나 `%20` 변환이 필요해진다.
- 이름만 봐도 어떤 화면인지 알 수 있게 `화면-상태` 형태로 짓는다 (`post-analysis-loading`).

### 이미지 용량
- 스크린샷이 늘면 저장소가 커진다. JPG로 두고 가로 폭은 필요한 만큼만 쓴다. 한 번 커밋하면 기록에 남는다.

## 5. 트러블슈팅

### 5-1. 한글·공백 파일명

| | 내용 |
|---|---|
| 증상 | 새 스크린샷이 `Ai 게시물 분석 완료.jpg`처럼 공백·한글 이름이었고, 나머지 이미지는 영문 kebab-case |
| 원인 | 캡처 도구의 기본 이름을 그대로 둠 |
| 해결 | `post-analysis-done-1.jpg` 등 영문 이름으로 직접 변경한 뒤 README에 연결 |

### 5-2. 이미지를 넣었는데 README에는 하나만 연결돼 있었음

| | 내용 |
|---|---|
| 증상 | `docs/images/web/`에 19장이 있는데 README에는 새로 넣은 4장만 연결됨 |
| 원인 | 나머지 15장은 파일만 추가하고 README에 링크를 만들지 않았음. 4장만 먼저 넣고 "나머지는 따로 섹션이 필요하다"고 설명했다가 오히려 혼란을 줬음 |
| 해결 | 19장을 모두 열어 내용을 확인한 뒤 `## 웹 화면` 섹션 하나에 흐름 순서로 정리 |
| 교훈 | 이미지를 넣을 때는 폴더의 파일 목록과 README 링크를 대조해서 빠진 것이 없는지 확인 (`grep -c images/web README.md`) |

### 5-3. 두 분석의 스타일 비율이 똑같이 50/30/20

| | 내용 |
|---|---|
| 증상 | 서로 다른 두 사진(게시물 기반, 독립 업로드)의 분석 완료 화면에서 캐주얼 50 · 댄디 30 · 미니멀 20으로 같음 |
| 원인 | **미확인.** 우연일 수도, LLM이 같은 틀로 답하는 것일 수도 있음 |
| 조치 | 이번 브랜치에서는 고치지 않음. 사진을 더 바꿔 가며 비율이 달라지는지 확인이 필요 |

### 5-4. LLM 실패 화면에서 "스타일 비율" 제목만 남음

| | 내용 |
|---|---|
| 증상 | `post-analysis-llm-fail`, `analyze-llm-fail`에서 "스타일 비율" 제목 아래가 비어 있음 |
| 원인 | 스타일 점수가 없어도 결과 템플릿(`templates/analysis/_result_body.html`)이 제목을 항상 그림 |
| 조치 | 이번 브랜치는 문서만 다뤄서 고치지 않음. 점수가 없으면 제목을 숨기도록 템플릿을 고치면 됨 (별도 브랜치) |

### 5-5. 이 브랜치에 섞이면 안 되는 변경

| | 내용 |
|---|---|
| 상황 | `cv_service/app/interpretation.py`(Gemini 모델 교체)가 수정된 채로 남아 있었음 |
| 해결 | 이 브랜치의 주제(문서)와 달라서 커밋하지 않고, 별도 `fix/` 브랜치에서 처리하기로 함 |
| 팁 | `git add .` 대신 파일·폴더를 골라서 `git add`하면 이런 변경이 섞이지 않음 |
